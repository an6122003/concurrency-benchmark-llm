Big models and the GPU memory setting

The NVIDIA App sets how much of the 128 GB is dedicated to the GPU (50 GB at first here, 96 GB at most). At 50 GB, CUDA can still address — GB, because Windows lends the rest as shared memory, so big models load either way. Method

  • Runtime: llama.cpp b11671 (CUDA 13, Windows on Arm) with every layer on the GPU and flash attention on. llama-bench for raw speed, llama-batched-bench for the engine ceiling, and the concurrency-benchmark-llm suite against llama-server for what a person feels.
  • Server: one slot per simulated person, a unified KV cache, prompt caching off so every request pays its full prompt reading, and reasoning off so answers are visible text (gpt-oss at low effort).
  • Speculative decoding is off unless a chart says otherwise; MTP uses Hermes Agent's preset of 2 draft tokens.
  • GPU memory setting: 96 GB for the final runs. The smaller models fit entirely in dedicated memory at either setting. Qwen3.8-Flash-Next appears only in the memory section, because at 96 GB it starves Windows of RAM.
  • Nemotron 3.5 Super kept the GPU busy at low power while decoding, which suggests its speed is limited by today's kernels rather than by memory bandwidth; newer llama.cpp builds may run it faster.
  • Power: Windows set to Best performance. llama-bench, speculative decoding, the coding test and the memory tests ran on a 65 W USB-C charger, pausing below 30% battery to recharge; the concurrency suites, MTP and batched runs ran on a 140 W charger.
  • DGX Spark numbers come from llama.cpp's published DGX Spark benchmark table for the same command.
